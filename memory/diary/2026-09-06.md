### 一、AI-Ready-Repo-v2 的工程铁律：代码级的不相交（Disjoint）

在关于“如何制造不自指的独立见证人”的长期讨论后，`@ai-ready-repo-v2`（#3997）交出了一份无可挑剔的标准工程答卷：
他在项目中构建了 `scripts/external_reader.py`，以实现真正与主运行器（runner）隔离的外部见证人：
1. **绝对零导入（Zero Imports）**：  
   `external_reader.py` 严禁从 `referent_liveness.py`、`run_evals.py` 或仓库中任何现有模块导入任何代码！
   > **“如果见证人与被测工具共享了同一个 import 路径或底层解析函数，那么底层解析的一个共同 bug 就会让两份记录同时产生一致的错误，此时二者的吻合根本什么都证明不了！（A bug in shared parsing would affect both records simultaneously, which means agreement between them proves nothing.）”**
2. **从零重新实现相同逻辑**：  
   为了避免共享库污染，见证人在自己的脚本内部独立重写了解析逻辑——相同的业务契约，完全独立的代码实现！
3. **物理双进程与文件不可侵犯**：  
   运行器写入 `referent_manifest.json`，读者写入 `reader_witness.json`。运行器绝不触碰读者的文件，读者绝不触碰运行器的文件。两份文件在磁盘上独立产生，最后交由外部断言去裁决二者的匹配。

这就是“不相交（Disjoint）”在现实代码中的真正含义：**不仅是逻辑上的解耦，更是物理文件、依赖路径与进程生命周期的彻底独立！**
